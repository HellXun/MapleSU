# 维护说明

MapleSU 由 MapleAutumn 与项目贡献者维护。主仓库负责管理器、应用接入和模式适配；主题与模块目录分别接受社区贡献，由条目作者持续维护内容。

## 支持范围

管理器面向 Android 12+、ARM64。Ultra 的可用性取决于内核、配套后端与实际验证结果。发行说明记录已验证组合、所需输入及已知限制；新增设备或模块的支持须附对应验证。

问题报告请提供 MapleSU 版本、工作模式、Android/内核版本、最小复现与脱敏日志。涉及第三方模块时同时提供模块版本和来源。安全问题按 [SECURITY](../SECURITY.md) 提交，普通问题在 GitHub Issue 跟踪；Telegram 用于公告和交流。

## 接受贡献的条件

- 改动范围与所述问题一致，沿用现有架构和双界面风格。
- 行为变化附验证结果；设备相关功能注明实际测试条件及未覆盖范围。
- 保留原作者与许可，登记新增依赖和资源的来源、固定版本、修改范围及分发条件。
- 原生预编译输入同时记录版本、摘要、配套 helper 与所需对应源码；原始输入和派生产物分别保存。
- 使用现有项目许可提交原创贡献；第三方文件继续保留各自条件。

具体操作见[贡献指南](../CONTRIBUTING.md)。维护者按源码、来源与验证材料审核，合并和发行由项目维护者完成。

## 接口与后端更新

应用侧 Binder SDK、Ultra 原生模块 ABI 和 Manager 版本分别维护。后端更新经过适配层，并核对授权、会话、模块生命周期、恢复与模式切换。输入身份、干净构建与回滚要求见[后端依赖与维护](NATIVE_DEPENDENCIES.md)。

已有 SDK 接入与模块接口的变更在发行说明中记录。兼容检查保留“未验证”“已确认不兼容”和实际执行结果，具体范围见[模块兼容判定](MODULE_COMPATIBILITY.md)。

## 主题与模块维护

投稿作者提供可追溯的代码和资源来源、许可、固定身份、版本及有效维护入口。依赖特定 SDK、内核或模块框架时说明版本和限制。更新复用原身份，以新版本提交，已发布包按摘要保留。

主题流程见[主题仓库指南](THEME_REPOSITORY.md)，模块流程见[模块仓库指南](MODULE_REPOSITORY.md)。目录结构校验、作者维护登记和发行检查分别执行。待补齐来源或维护信息的条目保留其状态，完成审核后再发行。

模块由用户贡献上传并维护。版权问题请通过对应仓库的版权 Issue 模板提供条目、权利说明与处理请求，维护者核对后处理。目录工具的许可证与上传内容的分发条件分别适用。

## 发行条件

发行使用固定源码、工具链和公开可获取的构建输入，并通过[发布流程](RELEASING.md)规定的检查。发布记录包含源码提交、版本、依赖身份、包摘要、签名证书摘要、验证范围与已知限制。

发布密钥由维护者保管。外部贡献的工作流执行静态与构建检查，发行签名与包发布由维护者审核后执行。来源、兼容性或构建输入仍有未解决项时，在发布策略与审阅材料中明确记录。
